Tool definitions prototype

A throwaway prototype for the ticket "How are OpenAPI tool definitions generated and projected to MCP and Flue tools?"

The question. Every tool is described by one OpenAPI document, its tool definition. The tools come from four sources:

  • a plugin's native tool;
  • a harness tool;
  • a remote MCP server;
  • a REST API that already has an OpenAPI spec.

From that one document the harness derives an MCP tool and a Flue (pi-agent-core) tool. It narrows the set by the user's role and the agent's request, marks what the mode will ask about, and preconfigures the agent session.

The interesting part is where the projections lose or bend something. Each tool below lists those gaps.
